# Sprint Contract — F017: Multiple project domains per cluster

Feature: F017 — each project's preview domain served by the same team cluster with its own wildcard DNS + cert
Phase: 05 — Multi-repo, reusable platform
Date: 2026-09-30

## 1. Scope & Acceptance Criteria
- [ ] `bootstrap/a7-project-domain.sh --domain D [--parent-zone P] [--apply]` (dry-run default, idempotent, context-guarded)
- [ ] Azure DNS zone D; delegation: NS records in parent Azure zone P, or printed for the registrar
- [ ] Wildcard `*.D` A → Traefik LB (stale IP replaced)
- [ ] cert-manager UAMI gets DNS Zone Contributor on D; ClusterIssuer `letsencrypt-dns-<slug>` (hostedZoneName D) + Certificate
      `wildcard-<slug>` in `traefik` ns
- [ ] Secret appended to Traefik default TLSStore `certificates` (default cert unchanged); SNI serves the right cert
- [ ] a6 `PREVIEW_DOMAIN` overridable per repo; teardown deletes `PROJECT_DOMAINS` zones
- [ ] e2e: `shop.preview.nimat.dev` on the live cluster; smoke on both domains → valid HTTPS (issuer Let's Encrypt, SAN matches)

## 2. Edge cases & failure paths
- Invalid domain / parent (case, leading `-`, no dot, not under parent, missing value, unknown flag) → exit 2, no cloud call
- Idempotent re-run (zone, NS, A, role, TLSStore entry present) → no mutation
- TLSStore with existing certificates → append via JSON patch; without → merge patch; default cert never touched
- No LB IP / no cert-manager identity / cert not Ready → fail before TLSStore change
- Wrong kube context → refuse
- N/A: UI, concurrency (operator-run).

## 3. E2E scenario(s)
`a7 --domain shop.preview.nimat.dev --parent-zone preview.nimat.dev --apply` → cert Ready; `smoke.sh --domain shop.preview.nimat.dev`
and `smoke.sh --domain preview.nimat.dev` both PASS; `openssl s_client` shows the right SAN per host.

## 4. Plan
fakes → tests → a7 → a6/teardown → init → live apply → smoke ×2 → PR.

## 5. Out of scope (parked)
Removing a single project domain (issuer/cert/TLSStore entry) — lifecycle moves to OpenTofu/Flux (F019/F020).

## 6. New dependencies
None.

## 7. Risks
Let's Encrypt rate limits (50 certs/registered domain/week) — one wildcard per project domain, renewals only.
