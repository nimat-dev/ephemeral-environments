# Sprint Contract — F023: Pilot second repo

Feature: F023 — Second repository onboarded to the multi-repo platform, proving full tenant isolation
Phase: 05 — Multi-repo, reusable platform
Date: 2026-10-01

## 1. Scope & Acceptance Criteria
- [x] Second repository (`nimat-dev/shop`) onboarded via OpenTofu `repo-onboarding` in `platform/envs/nimat/repos.tf`:
      Entra app + SP + federated creds, AcrPush/AcrDelete on ACR, AKS Cluster User, GitHub `preview` environment with variables.
- [x] Generated k8s guard `preview-deployer-guard-shop` in `clusters/nimat/config/repos/shop.yaml` committed and synced by Flux,
      confining `shop` SP writes strictly to `preview-shop-*`.
- [x] Second repo configured to consume the kit at `@v1.1.0`, using domain `shop.preview.nimat.dev` and app `shop`.
- [x] Multi-tenant isolation verified with identical branch name (e.g., `feat/pilot`):
      - `todo` preview deployed at `feat-pilot.preview.nimat.dev` in namespace `preview-todo-feat-pilot`
      - `shop` preview deployed at `feat-pilot.shop.preview.nimat.dev` in namespace `preview-shop-feat-pilot`
      - Both return HTTP 200 with valid, distinct TLS certs served via Traefik SNI.
- [x] Isolated lifecycle:
      - Destroy/reap triggered from `shop` affects only `preview-shop-*` namespaces and images.
      - `todo` preview remains fully intact and accessible.
      - Clean teardown of test previews after verification.
- [x] Full verify green (`scripts/init.sh` BASELINE GREEN, bats suite, OpenTofu fmt/validate/test, check-architecture).

## 2. Edge cases & failure paths
- Namespace collisions: identical branch names in both repos generate distinct namespaces (`preview-todo-feat-pilot` vs `preview-shop-feat-pilot`).
- Guard boundaries: `shop` deployer SP cannot touch `preview-todo-*` or cluster system namespaces (VAP enforces).
- SNI / TLS routing: `preview.nimat.dev` and `shop.preview.nimat.dev` served correctly on the shared Traefik ingress IP.
- Image purge: purge in `shop` touches only `nimatpreviewacr.azurecr.io/shop/*` images.

## 3. E2E scenario(s)
1. Onboard `nimat-dev/shop` via `platform/envs/nimat/repos.tf` and `tofu apply`.
2. Commit and sync generated Flux guard manifest `clusters/nimat/config/repos/shop.yaml`.
3. Create/configure `nimat-dev/shop` repository with `.preview.yaml` and kit workflows.
4. Deploy `feat/pilot` in both `ephemeral-environments` (`todo`) and `shop`.
5. Curl both endpoints, verifying HTTP 200 and TLS certificates.
6. Trigger destroy in `shop` and verify `shop` preview is removed while `todo` preview remains alive.
7. Clean up `todo` preview.
