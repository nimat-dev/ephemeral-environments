# Sprint Contract — F015: Repo-scoped preview identity

Feature: F015 — namespace `preview-<app>-<branch>`, `preview.repo` ownership label, destroy/reap own-repo only
Phase: 05 — Multi-repo, reusable platform
Date: 2026-09-30

## 1. Scope & Acceptance Criteria
- [ ] `preview_app APP REPO` → RFC 1123 slug ≤ 20 chars; APP (repo var `PREVIEW_APP`) wins, else the repo name of `owner/repo`
- [ ] `preview_namespace APP ID` → `preview-<app>-<id>`; > 63 chars → first 54 chars (trailing `-` trimmed) + `-` + 8-hex cksum of the full name (deterministic, portable: POSIX `cksum`)
- [ ] Host unchanged: `<id>.<PREVIEW_DOMAIN>` (per-project domain, DEC-040)
- [ ] Namespace labels add `preview.app=<app>`, `preview.repo=<slug(owner/repo), ≤63>`; annotation `preview.repo-original=<owner/repo>`
- [ ] Ownership rule `preview_owns REPO`: `managed-by=preview-bot` AND (`preview.repo` == mine OR label absent = legacy, pre-F015)
- [ ] namespace step: existing ns owned by another repo → refuse (exit 1), never relabel
- [ ] destroy: new name; if absent, legacy `preview-<id>` (no `preview.repo`) is deleted; other repo's ns refused
- [ ] reap: expired AND owned; other repos' namespaces never listed for delete
- [ ] purge: unchanged (deletes only its own `APP_IMAGE_NAME` repo; in-use set spans all previews = safer superset)
- [ ] Workflows pass `PREVIEW_APP` (deploy plan, destroy); repo from built-in `GITHUB_REPOSITORY`; a6 sets `PREVIEW_APP` (default `APP_IMAGE_NAME`)
- [ ] VAP guard + ClusterRole unchanged (`preview-*` still matches)
- [ ] check-architecture clean; FULL verify GREEN
- [ ] E2E: Deploy → `preview-todo-<id>` with labels, URL 200; Destroy → ns gone, 404; Reap dispatch green

## 2. Edge cases & failure paths
- Long app + long branch → hashed ns ≤ 63, stable across runs, distinct for distinct inputs sharing a 54-char prefix
- App/repo with uppercase, dots, underscores, unicode, only symbols (→ fallback to repo name; both empty → error)
- `GITHUB_REPOSITORY` missing → exit 2; malformed (no `/`) → exit 1
- Two repos, same branch → different ns; repo A destroy/reap never deletes repo B's ns
- Legacy name collision: this repo's legacy `preview-todo-x` vs new `todo`+`x` → same name; label absent → treated as ours (only one repo existed pre-F015)
- Label present but garbled/empty → not ours (refuse)
- N/A: concurrency (group per repo already), UI.

## 3. E2E scenario(s)
Push `feat/F015`, set repo var `PREVIEW_APP=todo` (a6 --apply), dispatch Deploy (branch feat/F015) → ns `preview-todo-feat-f015`,
labels checked with kubectl, URL 200; dispatch Reap (nothing of ours expired); dispatch Destroy → ns gone, URL 404.

## 4. Plan
tests (bats, red) → lib → preview-ci.sh → workflows + a6 → docs (DATA_MODEL, API_SURFACE, ARCHITECTURE) → init → e2e → PR.

## 5. Out of scope (parked)
Central reaper (F020); per-repo SP + VAP per app prefix (F020); multi-domain TLS (F017); `.preview.yaml` (F016).

## 6. New dependencies
None (`cksum` is POSIX).

## 7. Risks
Two repos on the SAME domain with the same branch still share a host → ingress conflict; DEC-040 makes domains per
project. Two repos with the same `APP_IMAGE_NAME` share an ACR repo (purge keeps in-use tags of both; onboarding must
give unique names — F020).
