# Sprint Contract — F019: Flux add-ons

Feature: F019 — in-cluster add-ons managed by Flux (AKS `microsoft.flux` extension), installed by OpenTofu
Phase: 05 — Multi-repo, reusable platform
Date: 2026-09-30

## 1. Scope & Acceptance Criteria
- [ ] OpenTofu `team-cluster`: `azurerm_kubernetes_cluster_extension` (microsoft.flux) + `azurerm_kubernetes_flux_configuration`
      (public repo over HTTPS, kustomizations `releases` → `config`, garbage collection on); `var.flux = null` → none
- [ ] `clusters/base/releases`: HelmRepositories + HelmReleases (traefik, cert-manager, keda, http-add-on dependsOn keda), same
      names/namespaces/versions/values as a1–a4 → adoption, no reinstall; drift detection on with ignores for runtime fields
- [ ] `clusters/base/config` (ClusterRole) + `clusters/nimat/{releases,config}`: cert-manager WI client id, issuers + certs per domain,
      TLSStore, deployer binding + VAP guard (identical to a5)
- [ ] Fits 1× D2as_v7: Flux trimmed (no notification-controller, 50m controllers) + KEDA core 50m; headroom recorded
- [ ] Proof: Flux Ready; kustomize + helm drift reverted; a removed release reinstalled from scratch; smoke + deploy regression green
- [ ] a1/a3/a4 marked superseded (kept for non-Flux clusters, DEC-042)

## 2. Edge cases & failure paths
- Adoption: storageNamespace must equal targetNamespace (else Flux would install a second release)
- Runtime-injected caBundles (cainjector, KEDA cert rotation) → perpetual drift loop unless ignored
- HPA/KEDA-owned replicas → ignored
- CPU starvation on install (kustomize-controller Pending; KEDA surge deadlock) → trims
- Provider polling bug on extension update ("text/plain") → verify in Azure, re-plan clean
- Bad flux source (ssh URL / path without ./) → validation error
- N/A: UI.

## 3. E2E scenario(s)
Flux Ready on live cluster; delete ClusterRole → restored; tamper Flux-owned Deployment field → corrected; `helm uninstall
http-add-on` → reinstalled; smoke PASS; Deploy (2 components) + Destroy green.

## 4. Plan
manifests → tofu → apply → fix CPU + drift loops → proofs → tests (flux.bats, tofu test) → init → PR → merge → point Flux at main.

## 5. Out of scope (parked)
A brand-new cluster built end to end from OpenTofu + Flux (subscription quota allows one cluster; Docker unavailable for kind).

## 6. New dependencies
Flux via the AKS extension (Microsoft-managed version); Microsoft.KubernetesConfiguration provider registration.

## 7. Risks
~300m CPU left for previews (3 awake components). More → bump node SKU (DEC-041), not node count.
